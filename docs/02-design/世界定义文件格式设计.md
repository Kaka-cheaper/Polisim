# 世界定义文件格式设计

## 一、文档目标

本文件定义 `World Definition` 的第一版文件格式，用于描述一个仿真世界的静态结构。

第一版目标：

1. 能支撑当前 MVP 场景
2. 能被 YAML 直接表达
3. 能被 JSON Schema / Pydantic 校验
4. 不追求过度抽象

## 二、职责边界

`World Definition` 只定义“这个世界允许什么存在、允许什么发生”。

它负责：

1. 实体类型
2. 属性模板
3. 关系类型
4. 动作类型
5. 消息类型
6. 环境变量定义
7. 感知范围定义
8. 决策模式定义
9. 运行默认参数

它不负责：

1. 具体实体实例
2. 初始状态
3. 某次仿真的轮次配置
4. 某次仿真的预设事件
5. 具体业务规则执行逻辑

这些分别属于 `Scenario` 和 `Rules`。

## 三、顶层结构

第一版 YAML 顶层建议如下：

```yaml
version: "0.1"
world:
  id: market-competition
  name: 多组织竞争与合作世界

entity_types: {}
relation_types: {}
message_types: {}
action_types: {}
environment: {}
defaults: {}
```

## 四、字段设计

### 4.1 world

用于描述当前世界定义本身。

建议字段：

```yaml
world:
  id: market-competition
  name: 多组织竞争与合作世界
  description: 用于模拟企业、监管方、媒体、用户群体和供应方的互动
```

约束：

1. `id` 必填，作为唯一标识
2. `name` 必填
3. `description` 可选

### 4.2 entity_types

用于定义实体类型模板。

建议结构：

```yaml
entity_types:
  Company:
    description: 市场中的企业主体
    decision_mode: llm
    activation:
      on_message: true
      decision_interval: 1
      wake_on:
        - environment_changed
        - relation_changed
        - action_finished
    perception:
      scope: relation
      include_relations: [competition, alliance, supply_dependency, influence, trust]
    attributes:
      market_share:
        type: number
        min: 0
        max: 100
        default: 10
      cash:
        type: number
        min: 0
        default: 100
      reputation:
        type: number
        min: 0
        max: 100
        default: 50
      strategy_bias:
        type: enum
        values: [aggressive, balanced, conservative]
        default: balanced
    actions:
      - promote
      - change_price
      - seek_alliance
      - expand
      - shrink
      - lobby_regulator
      - attack_competitor
      - stabilize_supply
      - do_nothing
```

约束：

1. 每个实体类型必须声明 `decision_mode`
2. 每个实体类型必须声明 `attributes`
3. 每个实体类型必须声明可执行 `actions`
4. 第一版 `decision_mode` 仅允许：`llm` / `rule` / `random`

### 4.2.1 activation

用于定义实体类型的激活策略。

运行时不应把激活条件硬编码在代码里，而应读取实体类型声明的 `activation` 配置。

建议结构：

```yaml
activation:
  on_message: true
  decision_interval: 3
  wake_on:
    - environment_changed
    - relation_changed
    - action_finished
  environment_triggers:
    - field: policy_pressure
      gte_delta: 10
  attribute_triggers:
    - field: reputation
      lte: 20
```

字段说明：

1. `on_message`
   - 收到消息时是否激活
2. `decision_interval`
   - 最短决策间隔，单位为 tick
3. `wake_on`
   - 关键事件触发器
4. `environment_triggers`
   - 环境变量变化触发条件
5. `attribute_triggers`
   - 实体关键属性触发条件

约束：

1. `activation` 可选，但建议所有可决策实体都声明
2. 若未声明 `decision_interval`，默认值为 `1`
3. 第一版 `wake_on` 只允许：`environment_changed`、`relation_changed`、`action_finished`

### 4.3 relation_types

用于定义关系类型。

建议结构：

```yaml
relation_types:
  competition:
    description: 竞争关系
    directed: false
    transient: false
  alliance:
    description: 合作关系
    directed: false
    transient: true
  influence:
    description: 影响关系
    directed: true
    transient: true
```

约束：

1. `directed` 必填
2. `transient` 必填

### 4.4 message_types

用于定义系统内允许流转的消息类型。

建议结构：

```yaml
message_types:
  policy_signal:
    description: 政策信号消息
    delivery: broadcast
    payload:
      signal:
        type: string
      strength:
        type: number
  cooperation_request:
    description: 合作请求
    delivery: direct
    payload:
      proposal:
        type: string
```

第一版 `delivery` 仅允许：

1. `direct`
2. `broadcast`
3. `by_relation`

这些值只定义**路由语义**，不定义投递时机。

也就是说：

1. `delivery` 决定消息发给谁
2. 消息何时可见由 `Runtime` 的统一消息时序机制决定
3. 第一版不允许某个消息类型单独覆盖“当前 tick 可见/下一 tick 可见”这类时序规则

### 4.5 action_types

用于定义动作类型、前置条件输入、效果类型。

**D-014 扩充**（2026-04 落地）：每个 param 除 `type`/`required` 外，还可声明 `description`/`default`/`min`/`max`/`values`/`entity_type_filter` 共 6 个可选字段——给 LLM 更准确的语义提示，给 Runtime random mode 更合理的填值依据，给 Rules 更细的强约束（详见 `docs/02-design/decisions/D-014-动作参数强Schema化.md`）。

建议结构：

```yaml
action_types:
  promote:
    description: 发起宣传行动
    actor_types: [Company]
    params:
      budget:
        type: number
        required: true
        description: 推广预算（货币单位），必须 ≤ 当前 cash      # D-014
        default: 10                                            # D-014
        min: 0                                                 # D-014
    effects:
      - kind: self_attribute
      - kind: environment
      - kind: message
  seek_alliance:
    description: 发起合作请求
    actor_types: [Company]
    params:
      target_id:
        type: entity_ref
        required: true
        description: 目标 Company 的 entity id                  # D-014
        entity_type_filter: [Company]                          # D-014（限定类型）
      proposal:
        type: string
        required: true
        description: 合作内容关键词（自由文本）                  # D-014
    effects:
      - kind: message
      - kind: relation
```

**ParamSchema 跨字段约束**（由 Pydantic `_check_param_constraints` 强制）：

1. `default` 非 None 时，类型与 `type` 一致（number↔int/float、string↔str、boolean↔bool、entity_ref↔str）
2. `min`/`max` 仅在 `type=number` 时有意义
3. `values` 仅在 `type=string` 时有意义
4. `entity_type_filter` 仅在 `type=entity_ref` 时有意义
5. `min <= max`（若两者都给）
6. `default in values`（若 `values` 给了）

第一版 `effects.kind` 仅允许：

1. `self_attribute`
2. `relation`
3. `message`
4. `environment`

### 4.6 environment

用于定义全局环境变量模板。

建议结构：

```yaml
environment:
  variables:
    market_demand:
      type: number
      min: 0
      max: 100
      default: 50
    policy_pressure:
      type: number
      min: 0
      max: 100
      default: 30
    public_sentiment:
      type: number
      min: -100
      max: 100
      default: 0
```

### 4.7 defaults

用于定义运行级默认参数。

注意：这里存放的是**默认参数**，不是完整规则实现。

例如：

1. 可以定义默认冲突策略
2. 可以定义默认 fallback 动作
3. 可以定义默认效果顺序

但“如何检查前置条件、如何解释动作效果、如何真正处理冲突”仍属于 `Rules`。

建议结构：

```yaml
defaults:
  conflict_resolution: both
  max_messages_per_tick: 100
  fallback_action: do_nothing
  action_effect_order:
    - self_attribute
    - relation
    - environment
    - message
```

字段说明：

1. `conflict_resolution`
   - 默认冲突解决策略
2. `max_messages_per_tick`
   - 单 tick 消息上限
3. `fallback_action`
   - 决策失败或超时时使用的默认动作
4. `action_effect_order`
   - 动作效果的默认执行顺序

## 五、最小完整示例

```yaml
version: "0.1"
world:
  id: market-competition
  name: 多组织竞争与合作世界

entity_types:
  Company:
    description: 企业主体
    decision_mode: llm
    perception:
      scope: relation
      include_relations: [competition, alliance, influence, supply_dependency, trust]
    attributes:
      market_share: { type: number, min: 0, max: 100, default: 10 }
      cash: { type: number, min: 0, default: 100 }
      reputation: { type: number, min: 0, max: 100, default: 50 }
      strategy_bias: { type: enum, values: [aggressive, balanced, conservative], default: balanced }
    actions: [promote, seek_alliance, attack_competitor, do_nothing]

relation_types:
  competition: { directed: false, transient: false }
  alliance: { directed: false, transient: true }

message_types:
  policy_signal:
    delivery: broadcast
    payload:
      signal: { type: string }
      strength: { type: number }

action_types:
  promote:
    actor_types: [Company]
    params:
      budget: { type: number, required: true }
    effects:
      - { kind: self_attribute }
      - { kind: environment }
  do_nothing:
    actor_types: [Company]
    params: {}
    effects: []

environment:
  variables:
    market_demand: { type: number, min: 0, max: 100, default: 50 }

defaults:
  conflict_resolution: both
  max_messages_per_tick: 100
  fallback_action: do_nothing
  action_effect_order: [self_attribute, relation, environment, message]
```

## 六、校验规则

第一版至少校验以下内容：

1. `world.id` 唯一且非空
2. `entity_types`、`action_types`、`message_types` 名称唯一
3. `entity_types.actions` 中引用的动作必须存在
4. `action_types.actor_types` 中引用的实体类型必须存在
5. `defaults.fallback_action` 必须在 `action_types` 中存在
6. 属性若声明 `enum`，必须提供 `values`
7. 属性若声明 `min/max`，则 `min <= max`

## 七、第一版不做什么

第一版不在 `World Definition` 中支持：

1. 动态脚本执行
2. 复杂表达式 DSL
3. 语义增强层映射
4. 跨文件继承

第一版只解决一件事：

**把世界的静态结构定义清楚，并能被程序稳定校验和加载。**
