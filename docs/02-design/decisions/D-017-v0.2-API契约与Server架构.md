# D-017：v0.2 API 契约与 Server 架构

> **状态**：草案（2026-04-28 session 29 起草）→ 待评审实施
> **阶段标记**：v0.2 启动决策——v0.1 → v0.2 关键迭代节点
> **关联决策**：D-006（UI-ready 输出）/ D-008（Runtime 步进式接口）/ D-016（PromptContext）；与 D-014 / D-015 / D-016 不冲突
> **预计实施**：session 30+（spec 评审 → UI mockup → server 骨架 → WebSocket → React）

---

## 一、决策背景（Why）

### 1.1 触发节点

session 22 末用户决定 v0.2 路线 = **单仓库 + FastAPI WebSocket 后端 + React 实时态势前端**。session 28 末引擎严谨化彻底完成（v0.1.1 + 架构审查清债 + D-015 全量版），700 tests passing 0 回归——进入 v0.2 准备阶段。

### 1.2 现有契约证据（v1 沉淀）

D-006（UI-ready）+ D-008（步进式接口）已经把 v0.2 需要的 API 契约**事实上**写在 v1 内核：

| v1 已有 | v0.2 直接复用 |
|---|---|
| `EventRecord`（`@models/runtime_models.py:211`）—— 已 JSONL 序列化 | response_model 直接用 |
| `Snapshot`（`@models/runtime_models.py:487`）—— 已 JSON 序列化 | 同上 |
| `TickResult`（`@models/runtime_models.py:521`）—— 含 events + snapshot + paused_after | WebSocket 推送 payload |
| `AnalysisResult`（`@models/analysis_models.py`）—— 已 MD+JSON 双格式 | GET /analysis 直接返回 |
| `PromptContext`（`@models/llm_models.py:45`）—— 已 6 段可拆 | 前端"LLM 决策面板"消费 |
| `Intervention`（`@models/runtime_models.py:406`）—— 已 typed | POST /intervene request body |
| `Runtime.step() / pause() / resume() / intervene()` —— D-008 步进式 | 直接对应 endpoints |

**关键观察**：v0.2 不需要发明新的数据契约，**只需**把 v1 内核暴露为 HTTP / WebSocket。

### 1.3 用户提的考虑（架构师视角，session 28 末）

用户原话：

> "目前只是第一个版本到第二个版本的迭代过程，如果现在不考虑好后续的扩展和维护，我觉得不太好"

这一立场**正确**——v0.1 → v0.2 是**架构本质升级**（从 Python 包变成 HTTP 服务），不是单纯加功能。这种节点如果偷懒（直接把 FastAPI handler 跟 Runtime 紧耦合），未来重构（v0.3 多并发 / v0.4 鉴权 / v0.5 mobile 客户端）成本极高。

### 1.4 决策范围

本 spec 决定 v0.2 server 端架构**与**前端协作的 API 契约，但**不**决定：

- 前端具体 UI 布局（留给后续 UI mockup 文档）
- 静态 demo（GitHub Pages 部署）的具体形式（留给 v0.2 收尾决策）
- 数据库 / Redis 等持久化方案（v0.2 用磁盘 + 内存，演进路径见第七节）

## 二、架构决策（What）

### 2.1 三层抽象

v0.2 server 模块**必须**分三层，禁止任意两层直接耦合：

| 层 | 职责 | 文件落点 | 不做的事 |
|---|---|---|---|
| **Routes** | HTTP 协议层（参数解析 / 状态码 / response_model）| `server/api/v1/routes/*.py` | 业务逻辑（必须委托给 services） |
| **Services** | 业务逻辑（创建/推进/暂停 Runtime；查询历史 run）| `server/services/*.py` | HTTP 协议（参数从函数签名拿）|
| **Registry** | 多并发 Runtime 实例的内存生命周期管理 | `server/runtime_registry.py` | 持久化（v0.2 内存版） |

**交互规则**：

- **Routes** → 调 **Services**（依赖注入 via FastAPI Depends）
- **Services** → 调 **Registry** + **`core/`**（Runtime / EventLog / loaders / analysis）
- **Registry** → 持有 **`core.runtime.Runtime`** 实例
- **从不**：Routes 直接 import `core/runtime` 跑业务逻辑

### 2.2 数据 schema 复用策略

**复用现有 `models/`，不新建 `api/schemas.py` 翻译层**。

理由：

1. D-006 已保证 `models/` 中所有暴露字段都是 UI-ready
2. 翻译层会引入同步成本（session 27 F3 文档漂移就是同步失败的样本）
3. 单 dev 项目无需企业级"内部 vs 外部 schema"分层

**例外**：未来若内部模型需要屏蔽某些字段（如某些 LLM 配置不该公开），**那时**才加 `EventRecordPublic` 之类的视图模型——YAGNI 渐进，不预先翻译。

**但是**：**有些**确实是 v0.2 新增的请求/响应模型——它们落点在 `server/api/v1/`：

- `CreateRunRequest`（POST /runs 的 body）
- `ErrorResponse` / `ErrorBody`（错误格式）
- WebSocket message envelopes（`TickAdvancedEvent` / `PausedEvent` / ...）
- 列表查询的 `RunSummary`（仅含元信息，不含 events 全量）

这些是**新模型**而非"翻译已有"，落点在 server/ 而非 models/——保持清晰边界。

### 2.3 API 版本化策略

**所有 endpoint 走 `/api/v1/` 前缀**。理由：

- v0.3 引入破坏性变更时（如 ErrorResponse 改格式 / 新增必填字段），加 `/api/v2/` 不冲突
- OpenAPI 自动生成两份 doc：`/api/v1/openapi.json` + `/api/v2/openapi.json`
- v1 客户端在 v2 上线后仍可工作（弃用周期由 server 配置）

**WebSocket 同样走 `/api/v1/runs/:id/stream`**，便于 v2 引入新协议时兼容。

### 2.4 错误处理标准

`SimEngineError` 子类必须有**明确的 HTTP 状态码映射**（见第五节）。所有错误响应使用统一 `ErrorResponse` 格式：

```json
{
  "error": {
    "code": "SEMANTIC_VALIDATION_FAILED",
    "message": "语义校验失败，共 2 项问题",
    "issues": [
      {"field_path": "world.defaults.fallback_action", "kind": "fallback_action_not_handled", "detail": "..."}
    ]
  }
}
```

**禁止**：把 Python traceback 直接暴露给前端。

### 2.5 鉴权策略

| 版本 | 鉴权方式 | 部署模式 |
|---|---|---|
| **v0.2** | **不鉴权**——本地 server，绑定 127.0.0.1 | 单用户开发 |
| v0.3 | API token（环境变量 `POLISIM_API_TOKEN`）| 团队 / 远程开发 |
| v0.4 | OAuth + 多用户（每用户独立 runs/） | SaaS / hosted |

v0.2 spec 不写鉴权细节——但路由结构必须**预留**中间件位置（`server/api/v1/middlewares/auth.py` 占位文件）。

## 三、REST endpoints 完整清单

> **设计纪律**：每个 endpoint 标注 (a) 复用哪个现有 model 作 response_model；(b) 使用哪个 service 方法；(c) 失败时映射哪些 HTTP 状态码。

### 3.1 Run 管理

#### POST /api/v1/runs

创建新 run（启动一个 Runtime 实例）。

- **Request body**：`CreateRunRequest`
  ```python
  class CreateRunRequest(BaseModel):
      scenario_path: str            # 相对仓库根
      world_path: str | None = None # 默认 <scenario_dir>/world.yaml
      runtime_config: RuntimeConfig | None = None
      llm_provider: Literal["mock", "openai"] = "mock"
      provider_key: str | None = None  # config/llm.yaml 中的 providers key
      ticks_override: int | None = None
      run_id: str | None = None     # 显式 run_id；None 自动生成
  ```
- **Response 200**：`RunDetail`（含 run_id / world / scenario / config / status）
- **Service**：`run_service.create_run(req: CreateRunRequest) -> RunDetail`
- **错误**：
  - 400 → ValidationError（schema 错）/ FileNotFoundError（路径错）
  - 422 → SemanticValidationError（D-013 校验失败）
  - 500 → RulesLoadError（rules_module 解析失败）
  - 502 → ProviderError（openai 鉴权 / 网络）

#### GET /api/v1/runs

列出所有 run（活跃 + 已存档）。

- **Query params**：`status` (active/archived/all, default=all) / `limit` (default=50) / `offset` (default=0)
- **Response 200**：`list[RunSummary]`
  ```python
  class RunSummary(BaseModel):
      run_id: str
      world_id: str
      scenario_id: str
      status: Literal["active", "paused", "finished", "archived"]
      current_tick: int
      total_ticks: int
      created_at: datetime
  ```
- **Service**：`run_service.list_runs(status, limit, offset)`
- **错误**：500 → IO 错（runs_root 不可读）

#### GET /api/v1/runs/:run_id

run 详情（含完整 world / scenario）。

- **Response 200**：`RunDetail`
  ```python
  class RunDetail(BaseModel):
      summary: RunSummary
      world: WorldDefinition  # 复用 models/world_models
      scenario: Scenario      # 复用 models/scenario_models
      runtime_config: RuntimeConfig
  ```
- **Service**：`run_service.get_run(run_id)`
- **错误**：404 → run 不存在；410 → run 已 GC（v0.2 内存释放后磁盘 events.jsonl 仍能读，但 RunDetail 视为已存档）

### 3.2 Run 控制

#### POST /api/v1/runs/:run_id/step

推进一 tick。

- **Response 200**：`TickResult`（直接复用 `models/runtime_models.TickResult`）
- **Service**：`run_service.step(run_id) -> TickResult`
- **错误**：
  - 404 → run 不存在
  - 409 → PausedError（先 resume）
  - 410 → TerminatedError（已达 total_ticks）
  - 500 → RulesError（链超深 / 创建已存在实体）

#### POST /api/v1/runs/:run_id/pause

暂停运行。

- **Response 200**：`{"status": "paused", "tick": current_tick}`
- **Service**：`run_service.pause(run_id)`
- **错误**：404 → run 不存在

#### POST /api/v1/runs/:run_id/resume

恢复运行。

- **Response 200**：`{"status": "running", "tick": current_tick}`
- **错误**：404

#### POST /api/v1/runs/:run_id/intervene

应用人工干预。

- **Request body**：`Intervention`（直接复用 `models/runtime_models.Intervention`）
- **Response 200**：`EventRecord`（intervention_applied 事件，直接复用）
- **Service**：`intervention_service.apply(run_id, intervention)`
- **错误**：
  - 400 → Intervention 字段不合约（Pydantic 校验）
  - 404 → run 不存在 / target_actor 不存在
  - 500 → RulesError

### 3.3 状态查询

#### GET /api/v1/runs/:run_id/state

当前 WorldState（含所有实体属性 + 关系 + 环境 + 邮箱）。

- **Response 200**：`WorldState`（复用）
- **错误**：404

#### GET /api/v1/runs/:run_id/snapshots/:tick

指定 tick 的 Snapshot。

- **Response 200**：`Snapshot`（复用）
- **错误**：404 → run 或 tick 无快照

#### GET /api/v1/runs/:run_id/snapshots

列出已保存的 tick 快照编号。

- **Response 200**：`{"ticks": [0, 1, 2, ...]}`
- **设计意图**：前端"时间轴跳转"功能需要知道哪些 tick 有快照

### 3.4 事件 / 分析

#### GET /api/v1/runs/:run_id/events

事件查询（**支持分页 + 过滤**）。

- **Query params**：
  - `tick` (int, exact match)
  - `kind` (str, EventKind literal)
  - `actor_id` (str)
  - `limit` (int, default=100, max=1000)
  - `offset` (int, default=0)
  - `until_tick` (int, 上限——含)
- **Response 200**：`EventListResponse`
  ```python
  class EventListResponse(BaseModel):
      events: list[EventRecord]
      total: int
      has_more: bool
  ```
- **Service**：`run_service.query_events(...)` —— 优先内存 EventLog；run 已存档时读磁盘 events.jsonl
- **错误**：404 / 500 → IO 错

#### GET /api/v1/runs/:run_id/analysis

获取分析报告。

- **Query params**：`enhance` (bool, default=false) —— 是否触发 Phase C LLM 增强
- **Response 200**：`AnalysisResult`（复用）
- **错误**：
  - 404 → run 未跑完 / run 不存在
  - 502 → LLMProtocolError / ProviderError（仅 enhance=true 时）

#### POST /api/v1/runs/:run_id/analyze

显式触发分析（含可选 LLM 增强）。

- **Request body**：`AnalyzeRequest { llm_enhance: bool }`
- **Response 200**：`AnalysisResult`
- **设计意图**：与 GET 不同，POST 表示"重新生成"——前端"重跑增强"按钮调它

### 3.5 元信息

#### GET /api/v1/scenarios

列出可用场景。

- **Response 200**：`list[ScenarioSummary]`

## 四、WebSocket 协议

### 4.1 路径与连接

`GET /api/v1/runs/:run_id/stream` —— 升级到 WebSocket。

**前置条件**：run 必须存在且 active。run 已 finished 或不存在时连接立即关闭（4004 close code）。

### 4.2 消息形态

所有消息都是 JSON 对象，含 `event` 字段做 discriminated union：

```python
# server/api/v1/ws_events.py
class WSEventBase(BaseModel):
    event: str  # 由子类 Literal override

class TickAdvancedEvent(WSEventBase):
    event: Literal["tick_advanced"] = "tick_advanced"
    data: TickResult  # 复用

class PausedEvent(WSEventBase):
    event: Literal["paused"] = "paused"
    data: PausedPayload

class PausedPayload(BaseModel):
    tick: int
    breakpoint_ids: list[str]
    reason: Literal["manual", "every_tick", "breakpoint", "total_ticks"]

class RunFinishedEvent(WSEventBase):
    event: Literal["run_finished"] = "run_finished"
    data: AnalysisResult  # 自动跑 Phase A，前端可显示后选择是否手动 enhance

class ErrorEvent(WSEventBase):
    event: Literal["error"] = "error"
    data: ErrorBody  # 复用 server/api/v1/errors.ErrorBody

class PingEvent(WSEventBase):
    event: Literal["ping"] = "ping"
    data: dict = {}

class PongEvent(WSEventBase):
    event: Literal["pong"] = "pong"
    data: dict = {}
```

### 4.3 服务端推送时机

| 事件 | 触发条件 |
|---|---|
| `tick_advanced` | 每次 `runtime.step()` 完成后立即推送本次 TickResult |
| `paused` | TickResult.paused_after=True 或客户端 POST /pause |
| `run_finished` | TickResult.reached_total_ticks=True；自动跑 Phase A 后推送 |
| `error` | 推送过程中发生 SimEngineError；推送后 close(4500) |
| `ping` / `pong` | 30s 周期心跳 |

### 4.4 客户端可发送的消息

v0.2 **不接受**客户端通过 WebSocket 发命令——所有控制走 REST endpoints（pause / resume / intervene / step）。WebSocket 单向：server → client。

理由：

- 简化协议（不需双向命令分派）
- REST 已能覆盖所有控制语义；WebSocket 专注"事件订阅"
- 未来 v0.3 若要加双向命令（如客户端直接发 step），再扩协议

### 4.5 关闭码

- 1000（normal）—— 客户端主动断开 / run 跑完
- 4004 → run 不存在
- 4005 → run 已 finished（404 升级为 4004 系列）
- 4500 → 服务端错误（SimEngineError）
- 4503 → registry 满（多并发上限）

## 五、错误处理标准

### 5.1 ErrorResponse schema

```python
# server/api/v1/errors.py
class ErrorBody(BaseModel):
    code: str            # 机器可读，前端按此分发处理
    message: str         # 人类可读，可显示
    issues: list[dict] | None = None  # 详细子项

class ErrorResponse(BaseModel):
    error: ErrorBody
```

### 5.2 SimEngineError → HTTP 映射表

```python
# server/api/v1/errors.py
ERROR_MAP: dict[type[SimEngineError], tuple[int, str]] = {
    # 4xx 客户端错误
    InvalidStateError:        (400, "INVALID_STATE"),
    SemanticValidationError:  (422, "SEMANTIC_VALIDATION_FAILED"),
    PausedError:              (409, "RUNTIME_PAUSED"),
    TerminatedError:          (410, "RUNTIME_TERMINATED"),
    # 5xx 服务端错误
    RulesError:               (500, "RULES_ERROR"),
    RulesLoadError:           (500, "RULES_LOAD_FAILED"),
    # 5xx 上游错误
    ProviderError:            (502, "LLM_PROVIDER_ERROR"),
    LLMProtocolError:         (502, "LLM_PROTOCOL_ERROR"),
}
```

### 5.3 全局异常处理器

```python
# server/api/v1/errors.py
async def simengine_error_handler(
    request: Request, exc: SimEngineError
) -> JSONResponse:
    status_code, code = ERROR_MAP.get(type(exc), (500, "UNKNOWN_ERROR"))
    body = ErrorBody(
        code=code,
        message=str(exc),
        issues=getattr(exc, "issues", None),  # SemanticValidationError 有
    )
    return JSONResponse(
        status_code=status_code,
        content=ErrorResponse(error=body).model_dump(),
    )
```

注册：`app.add_exception_handler(SimEngineError, simengine_error_handler)`。

### 5.4 前端约定

- **任何非 2xx 响应**——前端统一解析为 `ErrorResponse` 形态
- **`code` 字段做分支**——例如 `RUNTIME_PAUSED` 时弹"已暂停，是否恢复？"对话框
- **`message` 字段直接显示**——已是中文友好提示
- **`issues` 字段（可选）**——LLM 辅助建模"自我修复循环"前端消费 `SemanticValidationError.issues` 渲染各错误条目（D-013 设计意图）

## 六、Service 层设计

### 6.1 RunService

```python
# server/services/run_service.py
class RunService:
    """Run 生命周期管理 + 状态查询的业务逻辑层。

    所有方法**与 FastAPI 解耦**——不接受 Request 对象，只接受裸数据。
    可被 CLI / mobile / 第三方 SDK 同时使用。
    """

    def __init__(self, registry: RuntimeRegistry, runs_root: Path) -> None:
        self._registry = registry
        self._runs_root = runs_root

    def create_run(self, req: CreateRunRequest) -> RunDetail: ...
    def list_runs(
        self, status: str = "all", limit: int = 50, offset: int = 0
    ) -> list[RunSummary]: ...
    def get_run(self, run_id: str) -> RunDetail: ...
    def step(self, run_id: str) -> TickResult: ...
    def pause(self, run_id: str) -> dict: ...
    def resume(self, run_id: str) -> dict: ...
    def query_events(
        self,
        run_id: str,
        tick: int | None = None,
        kind: str | None = None,
        actor_id: str | None = None,
        limit: int = 100,
        offset: int = 0,
        until_tick: int | None = None,
    ) -> EventListResponse: ...
    def get_state(self, run_id: str) -> WorldState: ...
    def get_snapshot(self, run_id: str, tick: int) -> Snapshot: ...
```

### 6.3 StreamService

```python
# server/services/stream_service.py
class StreamService:
    """WebSocket 推送层——监听 EventLog 写入 + 广播给订阅的 ws clients。

    实现要点：
    - 每个 run 维护一个订阅者集合 set[WebSocket]
    - Runtime.step() 完成后调 broadcast(run_id, event)
    - WebSocket 断开时从集合移除
    - run finished 时主动 close 所有订阅
    """
    def subscribe(self, run_id: str, ws: WebSocket) -> None: ...
```

## 七、Runtime Registry 设计

### 7.1 v0.2 内存版

```python
# server/runtime_registry.py
class RuntimeRegistry:
    """活跃 Runtime 实例的内存注册表。

    职责：
    - register(run_id, runtime) → 注册新跑起来的 Runtime
    - get(run_id) → 返回活跃实例；不存在返 None
    - shutdown(run_id) → 关闭并 close()，从 registry 移除
    - shutdown_all() → server lifespan 结束时调用
    - max_concurrent → v0.2 限制 N=10（可配置）

    线程安全：v0.2 单进程 + asyncio——用 asyncio.Lock。
    """

    def __init__(self, max_concurrent: int = 10) -> None: ...
    def register(self, run_id: str, runtime: Runtime) -> None: ...
    def get(self, run_id: str) -> Runtime | None: ...
    def shutdown(self, run_id: str) -> None: ...
    def shutdown_all(self) -> None: ...
    def active_count(self) -> int: ...
```

**生命周期约定**：

- `register` 时检查 `active_count >= max_concurrent` → 拒绝（HTTP 503）
- 长时间无活动的 run（可配置 `idle_timeout_sec`）自动 shutdown 并标记 archived
- run 主动 finished（reached_total_ticks）时 → shutdown + 写终态到 events.jsonl

### 7.2 演进路径（v0.3+）

不在本 spec 落地，但**预留接口**便于未来切换：

| 演进方向 | 触发条件 | 实现思路 |
|---|---|---|
| 多进程 / Redis 共享 | server 集群部署 | RuntimeRegistry 替换为 RedisRegistry，记录 run 元数据；实际 Runtime 进程归属由分布式协调 |
| 持久化活跃 run | server 重启不丢未跑完的 run | 用 SQLite/PostgreSQL 存"暂停点"，重启从 EventLog 重放到该点 |
| 多用户隔离 | v0.4 SaaS | run_id 改为 `(user_id, run_id)` 复合键 |

## 十一、与 v0.1 → v0.2 过渡的整体定位

### 11.1 这是 Polisim 的"层数升级"

v0.1（含所有子版本到 0.1.1）= **5 层架构**：

```text
World Definition / Scenario / Rules / Runtime / Event Log + Analysis
                  （6 层等价描述见 README.md）
```

v0.2 = **7 层架构**（增加 server + web）：

```text
World Definition / Scenario / Rules / Runtime / Event Log + Analysis
                                            ↓
                               Server (FastAPI / WebSocket)
                                            ↓
                                    Web (React / Vite)
```

新加的两层**不接触 v1 内核**——只通过 D-006 / D-008 / D-016 已经定义的契约消费数据。这是 D-017 spec 的核心承诺。

### 11.2 维护性承诺

实施 D-017 后：

1. **v1 内核仍可独立工作**——`python -m cli run scenario.yaml` 全功能保留
2. **server 可独立测试**——所有 server/ 测试用 TestClient 不需要真实 React 前端
3. **前端可独立测试**——前端连 mock server 就能开发；后端连 mock 前端（curl + WebSocket 客户端）就能验收
4. **三层独立演进**——v0.3 升级 server（如加 Redis）不影响 v1 内核；v0.3 升级前端（如换 Vue）不影响 server

### 11.3 反规模复杂度的检查

D-017 严格遵守 AGENTS.md 4.5 节"禁止的通用 AI 习惯"：

- ❌ 不创建 `api/schemas.py` 翻译层（单 dev 项目过度工程）
- ❌ 不引入 ORM（v0.2 直接读 events.jsonl + 内存 registry）
- ❌ 不引入消息队列（WebSocket 直推够用）
- ❌ 不引入微服务架构（单进程 FastAPI）
- ✅ 抽**架构层**（routes / services / registry）—— 真实价值
- ✅ 复用**数据层**（models/）—— 不重复
