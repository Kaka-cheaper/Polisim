## 一、决策来源（session 29 用户对话）

8 项核心决策（按 session 29 与用户对话的顺序）：

| # | 维度 | 决策 |
|---|---|---|
| 1 | **目标用户** | 演示/教学（非技术观众主导）——非 debug 用、非研究用 |
| 2 | **核心看点** | 4 类全要：剧情 / LLM 决策 / 系统演化 / 最终报告 |
| 3 | **整体 Layout** | 展览馆三段式（跑前 → 跑中 → 跑完）—— 跟随仿真生命周期 |
| 4 | **节奏** | 默认自动跑 + 可暂停 + 实时干预 + 干预后恢复 |

| 6 | **场景范围** | 画廊页 + 2 现有 + 2-3 即将到来 + LLM 自动生成入口（v0.3+ 占位） |
| 7 | **跑中 Layout 风格** | 混合——`scenario.ui_layout` 字段三选一（entity_card / relation_graph / event_stream） |
| 8 | **覆盖范围** | 桌面 1280+ + 平板 1024+ + 中英切换；手机推迟 v0.3 |

## 二、核心用户故事（5 个）

围绕"演示/教学"目标用户：

### US-1：现场演示者（最核心）

> 我（用户）跑 `polisim serve` 后给同事 / 投资人 / 学生看 1-3 分钟 demo。
> 我希望：开场有清晰场景介绍 → 主体有自动跑 + LLM 决策可见 → 跑完有 AI 总结。
> 关键诉求：能在关键时刻**当场暂停 + 干预**，让观众看"如果...会怎样"的剧情分支。

### US-2：GitHub Pages 访客（自助探索）

> 我（任何人）点 `kaka-cheaper.github.io/Polisim` 链接进 demo。
> 我希望：场景画廊页有多个有趣选项；每个场景能"一键开始"自动跑完看完；事后能看 AI 总结。
> 关键诉求：**无需配置**，无需懂 YAML，无需懂 Polisim 内部架构。

### US-3：教师投屏教学

> 我（教师）在课堂上投屏 `polisim serve` 给学生看 multi-agent simulation。
> 我希望：每 tick 暂停几秒让我讲解；能展开 LLM 决策的 prompt 各段；能对比"干预 vs 不干预"两条剧情。
> 关键诉求：**可暂停可解释**——LLM 决策的 6 段 prompt（D-016）要能拆开看。

### US-4：互动剧场演示者

> 我希望演示能产生"哇府点"——观众正看着剧情发展，我突然点击 alice 卡片 → 强制让她拒绝 → 整个剧情转向。
> 关键诉求：**点击实体直接操作**，不要表单式选下拉、填字段。

### US-5：好奇 AI 怎么想的观众

> 我（观众）看 LLM 决策气泡上写"company_a 选了 promote 因为 cash 充裕"——我想看具体 prompt 怎么传的。
> 关键诉求：LLM 决策气泡可**展开** → 显示 D-016 PromptContext 完整 6 段（system_role / actor_view / perception / available_actions / language_hint / custom_segments）。

## 三、UI 区块全清单

按出现阶段组织：

| # | 区块 | 出现阶段 | 主要数据源（D-017 endpoint / WebSocket event） |
|---|---|---|---|
| 1 | **场景画廊页** | 入口 | `GET /api/v1/scenarios` |
| 2 | **场景介绍卡片**（开始 run 前）| 跑前 | `GET /api/v1/scenarios/:id` + 创建 run 后 `RunDetail` |
| 3 | **跑中主区**（3 种 layout 之一） | 跑中 | WebSocket `tick_advanced` → `TickResult` |
| 4 | **跑中控制条** | 跑中 | 客户端状态：auto/paused/speed |
| 5 | **跑中副区** mini dashboard | 跑中 | WebSocket `TickResult.snapshot.entity_state_summary` 等 |
| 6 | **LLM 决策气泡 / 面板** | 跑中 | `EventRecord(kind="decision_proposed").payload.prompt_context`（D-016）|
| 7 | **干预面板**（点击实体触发） | 跑中 | `POST /api/v1/runs/:id/intervene` |
| 8 | **跑完主区**（4 段 LLM 报告） | 跑完 | `GET /api/v1/runs/:id/analysis`（含 enhance 后的 4 段）|
| 9 | **跑完副区**（完整数据） | 跑完 | `GET /api/v1/runs/:id/events` + `GET /api/v1/runs/:id/snapshots/:tick` |
| 10 | **全局顶栏** | 全程 | run summary（run_id / status / current_tick）+ 中英切换 |
| 11 | **未来扩展占位**（自定义场景）| 画廊页 | v0.3+ 实施时换为 LLM 自动生成对话框 |

- 高级选项展开/折叠
- 速度选择保存到 client localStorage（下次记住）

- 点击 [📌 干预] 按钮（卡片右下角）→ 直接进入干预模式，等同点击卡片

**状态变化**：

- WebSocket 收到新 `tick_advanced` → 整个主区更新到最新 tick

  - LLM 想法气泡 fade-in（如有新 decision_proposed）
  - 属性变化箭头闪烁后渐隐（hint 用户注意变化）
- 实体被 EntityDestroy（D-015）→ 卡片 fade-out + 灰色拼贴样式 + "此实体已退场" 标识
- 实体被 EntityCreate（D-015）→ 新卡片 fade-in 到合适位置 + 高亮

#### 4.4.1 控制条（顶部固定）

```text
┌─ tick 3/5 · 🟢 自动播放 ────────────────────────[🌐 中/EN]──┐
│  [⏸ 暂停] [⏭ 单步] 速度 [ ●━━○━━○ 1x ▼ ]  [📊 副区] [🚪 退出]│
└────────────────────────────────────────────────────────────┘
```

**按钮语义**：

| 按钮 | 当前 status=running 时 | status=paused 时 | API 调用 |
|---|---|---|---|
| `[⏸ 暂停]` | 显示，可点 | 替换为 `[▶ 恢复]` | POST /runs/:id/pause |
| `[▶ 恢复]` | 隐藏 | 显示，可点 | POST /runs/:id/resume |
| `[⏭ 单步]` | 隐藏（自动跑时单步无意义）| 显示 | POST /runs/:id/step |
| 速度滑块 | 客户端状态——影响 `tick_advanced` 之间的渲染延迟 | 同 | 不调 API |
| `[📊 副区]` | 切换 mini dashboard 展开/折叠 | 同 | 不调 API |
| `[🚪 退出]` | 弹确认 modal → DELETE run（v0.2 不必，可只断 WebSocket）| 同 | DELETE /runs/:id（v0.3+）|

**速度档位**：

- `0.5x` —— tick 间隔 6 秒（教学慢速）
- `1x` —— tick 间隔 3 秒（默认）
- `2x` —— tick 间隔 1.5 秒（快速浏览）
- `4x` —— tick 间隔 0.75 秒（演示掉率）

**注意**：速度只控制**前端**渲染速率，**不影响** server 实际 step 速度。Server 收到 step 调用后立即 step（LLM 调用占用大头时间）；前端控制每 tick 渲染后等多久再发下一个 step（自动跑模式）。

- A. `react-force-graph-2d` —— 力导向，易上手，文档好

- cytoscape 包大小 +100KB（vs react-force-graph ~50KB）——但只在加载 RelationGraphLayout 路径时才下载（lazy loading），**不影响首屏**。
- 未来 0 迁移成本 vs 当下多花半天学习——长期收益明显。

**v0.2 装包**：`cytoscape` + `react-cytoscapejs` + `cytoscape-cose-bilkent`（高质量 force layout）。

**v0.3+ 扩展**：`cytoscape-dagre`（hierarchical）+ `cytoscape-popper`（hover tooltip）+ 算法 extensions。

### 11.9 数据流与生命周期

#### 跑中数据流（最关键）

```text
WebSocket 推送 tick_advanced (TickResult)
  │
  ▼
useRunStream 收到 → 更新内部 state：
  - events 累加 result.events
  - snapshots 存最新 result.snapshot
  - prevSnapshot = 上一 tick 的 snapshot（diff 用）
  - latestTick = result.snapshot.tick
  │
  ▼
Running 组件 re-render
  │
  ├─ TopBar / ControlBar 同步 status / tick
  ├─ <Layout> 拿 entities / relations / events
  │   └─ EntityCard 用 prevSnapshot diff 算 ↑5/↓20 箭头
  ├─ MiniDashboard 用累积 history 重绘折线
  └─ 所有"动画"由 framer-motion 自动处理（key 变化触发过渡）

WebSocket 推送 paused (PausedEvent)
  │
  ▼
useRunStream 设 status="paused" + 显示 reason toast
  │
  ▼
ControlBar 切按钮（[⏸ 暂停] → [▶ 恢复]）

WebSocket 推送 run_finished (RunFinishedEvent + Phase A AnalysisResult)
  │
  ▼
useRunStream 设 finished=true / phaseA=result.data
  │
  ▼
Running 组件 router.push(`/runs/:id/finished`)
  │
  ▼
Finished 组件挂载 → useFinishedRun 立即用 phaseA 渲染骨架 → 异步 GET /analysis?enhance=true
```

#### 干预流程（§4.4.3 + §10.6 M4）

```text
用户点击 EntityCard
  │
  ▼
EntityCardLayout.onEntityClick(id)
  │
  ▼
Running.handleEntityClick:
  1. POST /pause (optimistic，不等 ws PausedEvent)
  2. setSelectedActor(id) → 渲染 InterventionDrawer
  │
  ▼
InterventionDrawer 表单
  │
  ▼
onSubmit(intervention):
  1. POST /intervene (拿 EventRecord)
  2. POST /resume
  3. close drawer
  │
  ▼
WebSocket 推下一 tick_advanced（含 intervention 后效果）
```
