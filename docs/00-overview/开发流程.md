# 开发流程

## 一、当前状态

项目当前处于：**系统设计前期**。

已完成：

1. 需求分析
2. 可用性与价值评估
3. 首个 MVP 场景定义
4. 需求审查与风险梳理

下一步应进入：**系统设计**。

## 二、文档阅读顺序

建议按下面顺序看文档：

1. `需求分析.md`
   - 看项目要做什么
2. `可用性与价值评估.md`
   - 看为什么值得做、与替代方案的区别，以及推荐技术路线
3. `MVP场景定义.md`
   - 看第一版到底先做什么
4. `需求分析审查.md`
   - 看目前还有哪些风险、假设和待确认事项

## 三、开发流程

1. **需求分析**
   - 明确项目定位、目标、边界、核心能力

2. **系统设计**
   - 设计世界定义文件格式
   - 设计场景文件格式
   - 设计规则层和事件轨迹结构
   - 设计核心接口和数据流

3. **技术选型**
   - 语言、框架、存储、LLM 接入方式

4. **原型验证**
   - 用首个 MVP 场景跑通最小闭环

5. **代码开发**
   - 按模块逐步实现

6. **测试与示例**
   - 验证场景可运行
   - 验证架构是否可复用到第二个场景

## 四、当前阶段的目标

系统设计阶段只解决三件事：

1. 世界如何定义
2. 仿真如何运行
3. 用户如何暂停、分析和干预

如果这三件事定义清楚，再进入代码开发。

## 五、未来演化目标

当前路线不是一次性做完所有能力，而是分阶段演化：

1. 第一阶段：跑通分层闭环
2. 第二阶段：验证第二个场景的复用性
3. 第三阶段：引入可选语义增强层，如知识图谱能力

核心原则是：

**先做对运行内核，再做语义增强层。**
