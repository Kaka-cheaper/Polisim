# 如何使用这套文档与配置体系

## 一、这份文档是给谁看的

这份文档是给第一次接触 `Polisim` 的读者准备的。

如果你现在的问题是：

1. 这些文档分别是干什么的
2. 我应该从哪一份开始看
3. 我如果要新建一个场景，到底要改哪些东西

那先看这一份。

## 二、先用一句话理解整个项目

`Polisim` 是一个**可配置的多实体仿真引擎**。

你先定义世界里允许有哪些实体、动作、消息和规则，再定义这次仿真里具体有哪些实体和初始状态，然后由运行内核推进仿真，并基于全过程输出分析结果。

## 三、先理解 6 个核心层

### 3.1 World Definition

回答：

**这个世界里允许有什么。**

它定义：

1. 实体类型
2. 属性模板
3. 关系类型
4. 动作类型
5. 消息类型
6. 环境变量
7. 默认运行参数

### 3.2 Scenario

回答：

**这次仿真具体是什么。**

它定义：

1. 有哪些具体实体
2. 它们的初始属性值
3. 初始关系是什么
4. 环境初始值是什么
5. 预设事件和断点是什么
6. 这次仿真跑多少轮

### 3.3 Rules

回答：

**这些动作和状态变化到底怎么生效。**

它负责：

1. 前置条件
2. 动作效果解释
3. 冲突处理
4. 状态约束

### 3.4 Runtime

回答：

**仿真怎么一轮一轮跑起来。**

它负责：

1. tick 推进
2. 消息投递
3. 激活实体
4. 收集动作提议
5. 调用规则层
6. 保存轨迹

### 3.5 Event Log

回答：

**仿真过程中发生过什么。**

它记录：

1. 动作提议
2. 动作执行
3. 消息发出
4. 状态变化
5. 快照
6. 干预事件

### 3.6 分析层

回答：

**如何基于轨迹生成即时分析和最终报告。**

## 五、如果你要新建一个场景，要改哪些东西

最常见的情况不是改引擎，而是**新建一个场景**。

这时通常只需要动下面几层：

### 5.1 一定会改

1. `World Definition`
   - 如果这个新场景需要新的实体类型、动作、消息、环境变量
2. `Scenario`
   - 一次仿真的具体实例、初始值、轮次、事件、断点

### 5.2 可能会改

1. `Rules`
   - 如果动作效果、前置条件、冲突逻辑和原场景不一样

### 5.3 通常不该改

1. `Runtime`
2. `Event Log`
3. `LLM 决策协议`

如果新建一个场景时你发现自己要去改 Runtime，大概率说明边界还被破坏了。

## 六、如果你要第一次真正实现它，先做什么

当前项目还处在设计阶段。

如果要进入实现，推荐顺序是：

1. 先把 `World Definition` 和 `Scenario` 的 schema 落成可校验结构
2. 再把 `Rules` 和 `Runtime` 的最小骨架写出来
3. 先让一个最小场景在没有真实 LLM 的情况下跑通
4. 再接入真正的 LLM 决策
5. 最后补即时分析和最终报告

## 七、如何判断你有没有看懂

如果你能回答下面 4 个问题，就说明你已经上手了：

1. 世界定义和场景的区别是什么？
2. 哪一层负责决定动作是否合法？
3. 哪一层负责推进 tick？
4. 为什么分析要基于事件轨迹，而不是只看最后状态？

## 八、这套文档目前不解决什么

这套文档目前主要面向：

1. 系统设计
2. 实现准备
3. 架构收敛

它还没有解决：

1. 最终用户界面怎么长
2. 规则编辑器怎么做
3. 场景模板库怎么做
4. 产品化体验怎么做
