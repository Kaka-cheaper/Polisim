# 最小示例 Walkthrough

## 一、目的

这份文档用一个最小例子，把下面这条链路串起来：

**世界定义 → 场景实例 → 仿真运行 → 轨迹输出 → 分析输出**

它不是完整教程，只是帮助你建立整体感觉。

## 二、我们要做一个什么最小例子

最小例子只保留 2 个实体：

1. `Company`
2. `Regulator`

目标是模拟一个非常简单的过程：

1. 企业可以宣传自己
2. 监管方可以发出政策信号
3. 企业会根据收到的政策信号决定是否继续宣传
4. 系统记录全过程并输出当前分析

## 三、第一步：写世界定义

你先定义“这个世界允许什么存在”。

最小世界定义里至少有：

1. 一个 `Company` 实体类型
2. 一个 `Regulator` 实体类型
3. 一个消息类型 `policy_signal`
4. 两个动作类型：`promote` 和 `do_nothing`
5. 一个环境变量 `policy_pressure`

这一步对应：

`02-design/世界定义文件格式设计.md`

你可以把它理解成：

**先搭一个棋盘，规定棋子种类和允许动作。**

## 四、第二步：写场景实例

然后你定义“这一次仿真里具体是谁在场上”。

最小场景里有：

1. 一个企业实例 `company_a`
2. 一个监管方实例 `regulator_main`
3. 一个初始环境值 `policy_pressure = 20`
4. 一个预设事件：在第 2 个 tick 发出更强的政策信号
5. 一个运行配置：总共跑 5 个 tick

这一步对应：

`02-design/场景文件格式设计.md`

你可以把它理解成：

**把具体棋子摆到棋盘上。**

## 五、第三步：运行时开始推进

Runtime 开始跑时，大致会做下面几件事：

1. 读取上一轮消息
2. 处理当前轮事件
3. 计算哪些实体被激活
4. 收集被激活实体的动作提议
5. 调用规则层校验和解释动作
6. 应用效果
7. 写入事件轨迹和快照

这一步对应：

`02-design/运行时与事件轨迹设计.md`

## 六、第四步：LLM 在哪里起作用

假设 `company_a` 的 `decision_mode = llm`。

在某个 tick 中：

1. Runtime 把企业当前属性、收到的消息、环境状态、允许动作列表传给 LLM
2. LLM 返回一个结构化动作，比如：
   - `promote`
   - `budget = 20`
3. Runtime 不会直接相信它
4. 规则层继续检查这个动作是否合法

如果 LLM 返回非法动作：

1. 会重试
2. 再失败则走 `fallback_action`
3. 若未定义 fallback，则执行 `do_nothing`

这一步对应：

`02-design/LLM决策协议设计.md`

## 七、第五步：规则层真正让动作生效

假设企业提议：

`promote(budget=20)`

规则层会做：

1. 检查企业现金是否足够
2. 如果合法，则生成效果
   - `cash - 20`
   - `reputation + 5`
3. 如果不合法，则拒绝动作或让它走 fallback

这一步对应：

`02-design/规则层设计.md`

## 八、第六步：系统留下轨迹

每个 tick 跑完后，系统会至少留下两类东西：

1. **Event Log**
   - 谁提议了什么动作
   - 谁执行了什么动作
   - 发出了什么消息

2. **Snapshot**
   - 当前 tick 结束后的实体状态
   - 关系状态
   - 环境状态

这就是后面分析的依据。

## 九、第七步：做即时分析

如果用户在第 3 个 tick 后暂停：

1. 分析层读取 `tick 0 ~ 3` 的事件轨迹
2. 读取当前快照
3. 提取最近几轮关键变化
4. 生成当前分析

输出可能包括：

1. 当前优势方是谁
2. 当前风险点是什么
3. 最近一轮的关键变化是什么
4. 如果继续运行，可能会怎样

## 十、第八步：做最终报告

仿真结束后：

1. 分析层读取全量事件轨迹
2. 读取全量快照
3. 生成最终总结

输出可能包括：

1. 全轨迹总结
2. 关键转折点
3. 哪个事件改变了局势
4. 最终建议

## 十一、这个最小例子真正说明了什么

它说明这套系统不是“让 LLM 自己即兴聊天”，而是：

1. 世界先被定义
2. 场景再被实例化
3. Runtime 负责推进
4. Rules 负责生效逻辑
5. LLM 只负责选动作
6. Analysis 负责解释轨迹

也就是说：

**系统的真相在 Runtime + Rules + Event Log 里，不在 LLM 自己的记忆里。**

## 十二、看完这个 walkthrough 后你应该知道什么

如果你看完后能回答下面 3 个问题，就说明已经建立了整体感：

1. 为什么世界定义和场景实例要分开？
2. 为什么 LLM 只负责动作选择，不负责直接改状态？
3. 为什么分析要读轨迹，而不是只读最终状态？
